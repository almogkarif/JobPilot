Scope
-----
1. Backward-compatible Local Mode (SQLite + local files + local Agent token).
2. Private Cloud Mode with Supabase Auth, PostgreSQL and private Storage.
3. Google OAuth and email/password browser authentication UI.
4. Single-owner cloud binding so a second Supabase account cannot read the private instance.
5. Local Mac Application Agent pairing with revocable device-specific tokens.
6. Secure CV download from the cloud Agent API and screenshot upload back to cloud Storage.
7. External scheduled-scan endpoint with a separate cron secret.
8. v0.2.0 career-track isolation remains intact in cloud mode.
9. Legacy SQLite -> cloud database migration, including older schemas and existing files.
10. Current Supabase publishable/secret API-key model plus legacy service_role compatibility.

Cloud auth/security tests
-------------------------
- /api/jobs and other private APIs require a Supabase user session in Cloud Mode.
- The first accepted cloud user must match JOBPILOT_OWNER_EMAIL.
- A different authenticated Supabase user receives HTTP 403.
- Public auth config exposes only Project URL + publishable key, never either
  server secret-key form.
- Agent device token is shown once, SHA-256 hashed at rest, and immediately stops
  authorizing after revoke.
- Cron endpoint rejects missing/incorrect X-JobPilot-Cron-Secret.
- New sb_secret_* Supabase keys are sent on apikey only and are never treated as
  JWT Bearer tokens; legacy service_role JWTs retain Bearer compatibility.
